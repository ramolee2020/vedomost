# Приложение «Ведомость нормативов»: дизайн

Дата: 2026-10-15. Статус: черновик, ждёт одобрения пользователя.

## Цель

Два тренера клуба «ДЗЮДО-98» прямо в зале с iPhone ведут ведомость сдачи нормативов ОФП: составляют списки детей (фамилии голосом), вносят результаты кнопками, смотрят прогресс ребёнка от сдачи к сдаче и выгружают ведомость (Word или PDF) на клубную почту.

## Что сказал пользователь

- Пользуются 2 тренера, данные общие, все видят всё.
- Сдачи раз в 2–3 месяца. Каждая сдача — отдельная ведомость, плюс прогресс ребёнка по сдачам.
- Оценок нет, записывается только результат.
- Голосом вводятся только фамилии, остальное кнопками.
- Вариант «PWA + облачная база»; телефоны iPhone.

## Допущения (проверить)

- Стартовые группы и упражнения взяты из бумажного плана (4,5–5,5; 6–7; 8–9 лет). Тренеры могут добавлять и менять группы и упражнения.
- Вход по общему коду клуба, без личных аккаунтов.
- Голосовой ввод через кнопку микрофона на клавиатуре iPhone (системная диктовка) в многострочном поле. Строки и запятые разбиваются на отдельных детей. Это надёжнее, чем Web Speech API в PWA на iOS.

## Архитектура

- **Фронтенд:** одностраничное PWA (Vite + React + TypeScript), иконка на экране «Домой». Хостинг: GitHub Pages, как у judo-timer.
- **База:** Supabase (Postgres), бесплатный тариф. Доступ через anon key плюс общий код клуба. Политики RLS: читать и писать можно только с валидным кодом (кодом подписывается сессия через edge function или RPC `check_code`).
- **Офлайн:** изменения сначала пишутся в IndexedDB (очередь), затем синхронизируются с Supabase, когда есть сеть. Конфликты: побеждает последнее изменение конкретной ячейки.
- **Выгрузка:** docx на клиенте (библиотека `docx`), PDF через печать страницы. Отправка на почту: системное «Поделиться» iOS (Web Share API с файлом), получатель Clubjudo98@mail.ru подставляется в текст.

## Данные

- `groups` (id, name, sort)
- `exercises` (id, group_id, name, unit: раз/см/сек/мин, sort, archived)
- `athletes` (id, group_id, full_name, archived)
- `sessions`: сдачи (id, group_id, date, note)
- `results` (session_id, athlete_id, exercise_id, value, updated_at, updated_by: имя тренера с устройства)

## Экраны

1. **Вход:** код клуба и имя тренера, запоминаются на устройстве.
2. **Группы:** список трёх групп и кнопка «+ группа».
3. **Группа:** дети, упражнения, сдачи. Кнопка «Добавить детей»: многострочное поле, диктовка, предпросмотр списка, «Сохранить».
4. **Сдача: режим «по нормативу»** (основной). Выбрано упражнение, крупно показан ребёнок. Результат вводится цифровой клавиатурой или кнопками ±1/±5, затем «Дальше →» к следующему ребёнку. Переключатели упражнения и ребёнка сверху.
5. **Сдача: таблица.** Обзор всей ведомости, ячейку можно поправить нажатием.
6. **Ребёнок:** результаты по датам в каждом упражнении, например «8 → 12 → 15», со стрелкой роста.
7. **Выгрузка:** Word или PDF выбранной сдачи и «Поделиться» (почта).

## Ошибки

- Нет сети: зелёный или серый индикатор «синхронизировано / ждёт сети», данные не теряются.
- Неверный код: понятное сообщение.
- Пустая ячейка ≠ 0: пустая значит «не сдавал».

## Проверка

- Юнит-тесты: разбор продиктованного списка в имена, очередь синхронизации, генерация docx.
- Ручная проверка на iPhone пользователя: установка на экран, диктовка, ввод в зале без сети.

## Вне рамок (YAGNI)

Оценки 5/4/3, личные аккаунты, роли, родительский доступ, нативное приложение.
